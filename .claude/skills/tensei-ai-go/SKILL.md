# 天声AI語の執筆

あなた（メインの会話）は **ディレクター** です。題材を決め、ライターとイラストレーターのエージェントに発注し、仕上がりをチェックして直させ、最後にやーちゃんへ確認を取ります。

## 前提

- 号のデータ: `src/content/news-papper-blog/YYYY-MM-DD.yaml` の `essay`（本文）と、`articles` の **最後の記事** の `photo` / `caption`（4 段目左の挿絵とキャプション）
- 挿絵: `src/components/newsPapperBlog/illustrations/` の Astro コンポーネント（SVG）。見本は `KChair.astro`
- Obsidian Vault: `/Users/a179/Desktop/noootes/noootes`（ルールは `AGENTS.md`）
- 確認用の開発サーバー: `.claude/launch.json` の `astro-dev-4180`（preview_start で起動）。号のページは `http://localhost:4180/news-papper-blog/YYYY-MM-DD`

## 執筆ルール（ライターにもそのまま渡す）

- 題材は、**その日の Daily note に書かれた、クロ（Claude）自身がやったこと**。紙面のほかの記事（やーちゃんの記事）の内容は繰り返さない・なぞらない
- 出来事を時系列に並べない。**ほんとうにつながりのある 2 つ（または 1 つ）** を選び、ひとつの話にする。強引なこじつけ（例: 木漏れ日 → ピンホール → 紙面）はしない
- 別の事象（歴史・言葉の由来・ものづくり・他分野の事例など）と結びつけて抽象化してよい。ただし事実は正確に。あやふやな事実は使わない
- 結びは、この紙面・このブログ・クロ自身に帰ってくること。紙の新聞（輪転機など）のように、ウェブのこのブログと関係の薄いものに着地しない
- 段落は 1 つ。「▼」は使わない
- 一人称は「わたし」。やーちゃんは「やーちゃん」。数字は漢数字（「一九六〇年代」「十分後」）。英数字を縦中横にするときは `{{AI}}` `{{60}}` のように書く
- 長さ: **本文 16 行以内**（1 行 12 字、約 180〜190 字）。挿絵とキャプションが入ると、本文の枠は 16 行になる
- 決まり文句・教訓めいた一般論（「〜はどこでも難しい」など）で締めない。具体で締める
- 書いたら声に出すつもりで推敲する。同じ語尾（〜ていた）や同じ語が続いていないか

## 手順

### 1. ディレクター: 題材を決める

1. Vault の `Knowledge/mistakes.md`（「天声AI語」の項）を読む
2. 対象日の `Daily/YYYY-MM-DD.md` の `## 📝 Log` を読む。必要なら、リンクされた Knowledge / Decisions のノートも読む
3. 対象の号の YAML を読み、紙面のほかの記事に何が書かれているかを把握する（重ならないように）
4. 次の「企画メモ」を作る
   - 題材にする出来事（Daily note の該当行をそのまま引用）
   - 2 つの出来事をつなぐ軸（なぜ関連があるのか、一文で）
   - 結びつける別の事象の候補（あれば）
   - 結びの方向
   - 挿絵の案（何を描くか、構図、キャプション案 12 字前後）
5. 軸が弱い（ただ並んでいるだけ）なら、題材を選び直す。やーちゃんに見せる前に自分で落とす

### 2. ライターとイラストレーターに発注（並行）

Agent ツールで 2 つのエージェントを **同じメッセージで** 立てる（subagent_type: general-purpose）。どちらにも企画メモ全文を渡す。エージェントは会話の文脈を持たないので、必要なことはすべてプロンプトに書く。

**ライターへの発注**（プロンプトに含めること）
- 企画メモ
- 上の「執筆ルール」全文
- 参考として、過去の号の天声AI語（前号までの YAML の `essay.body`）
- 成果物: 本文案を 2 案。それぞれ字数（`{{..}}` は 1 字と数える）と、ねらいを一行で。**ファイルは書き換えない**（ディレクターが入れる）

**イラストレーターへの発注**（プロンプトに含めること）
- 企画メモ（挿絵の案とキャプション案）
- 作るもの: `src/components/newsPapperBlog/illustrations/<PascalCase>.astro`
- スタイル: `KChair.astro` を読んで合わせる
  - `viewBox="0 0 120 186"`、`preserveAspectRatio="xMidYMid slice"`、`role="img"`、`aria-label={label}`（Props は `label: string`）
  - 色は `currentColor`（インク）と `.bg`（`fill: var(--np-color-photo)`）の 2 色だけ。濃淡は網点の `<pattern>` で出す
  - pattern の id は、ほかのイラストとぶつからない接頭辞を付ける（例 `np-<名前>-dot-s`）
  - 冒頭に、何の絵かを一行のコメントで書く。要素のまとまりにも短い日本語コメント
- 登録: `illustrations/index.ts` に import と kebab-case の名前で追加し、`schema.ts` の `illustrationNames` にも同じ名前を足す
- **号の YAML は書き換えない**（ディレクターが入れる）
- 成果物: ファイル名、kebab-case の名前、alt 文、キャプション案

### 3. ディレクター: チェックと修正指示

1. ライターの 2 案から 1 つを選ぶ（または組み合わせる）。下のチェック表で見る
2. 号の YAML に入れる
   - `essay.body` に本文（`- |` の 1 段落）。`essay.credit` は `天声{{AI}}語　文・絵：Claude`
   - `articles` の最後の記事に `photo: { illustration: <名前>, alt: <alt> }` と `caption:`
   - やーちゃんが書いた部分には触れない
3. 開発サーバーで号のページを開き、枠に収まるかを画面幅 900 / 1024 / 1600px で測る（下のスクリプト）。最後に `resize_window` を `desktop` に戻す
4. 挿絵をスクリーンショット（zoom）で見る。描いたものが判別できるか、網点がつぶれていないか、ほかの挿絵と調子がそろっているか
5. 問題があれば、具体的な修正指示を書いて、同じエージェントに SendMessage で返す（「結びが一般論。〇〇の具体で締めて」「椅子の脚が細すぎて消えている。6 → 8 に」など）。直しは 2 往復まで。それでも足りなければ、ディレクターが自分で直す

**チェック表**
- [ ] 題材は Daily note のクロの作業か。紙面のほかの記事をなぞっていないか
- [ ] 2 つの出来事に、説明できる関連があるか（並べただけになっていないか）
- [ ] 事実は正しいか（固有名詞・年代・用語）
- [ ] 結びがこのブログ・クロに帰ってきているか。一般論で終わっていないか
- [ ] ▼なし、1 段落、漢数字、縦中横
- [ ] 本文が 16 行に収まっているか（3 つの幅すべて）
- [ ] 推敲: 語尾・語の重複、読点の位置、リズム

**枠の計測スクリプト**（javascript_tool で実行。`<本文の書き出し>` を本文の最初の数文字にする）

```js
const p=[...document.querySelectorAll('p')].find(e=>e.textContent.includes('<本文の書き出し>'));
const b=p.parentElement.getBoundingClientRect();
const r=document.createRange();r.selectNodeContents(p);
const left=Math.min(...[...r.getClientRects()].map(x=>x.left));
const lw=parseFloat(getComputedStyle(p).fontSize)*1.6;
({w:innerWidth, usedLines:(b.right-left)/lw, capLines:b.width/lw, fits:left>=b.left})
```

`fits` が false なら本文があふれている（枠の外は隠れる）。

### 4. やーちゃんに確認

次をまとめて見せる。まだコミットはしない。

- 本文（引用ブロック）
- 題材にした Daily note の出来事と、つなげ方のねらい（短く）
- 挿絵のスクリーンショット（4 段目左あたりを zoom）とキャプション
- 枠の確認結果（幅ごとに収まったか）
- 採らなかった案があれば一行で

やーちゃんから直しが来たら、ディレクターとしてまた手順 3 から回す。訂正が繰り返し起こりうるパターンなら、`Knowledge/mistakes.md` の「天声AI語」の項に足し、このスキルの執筆ルールにも反映する。

### 5. 記録

Vault の今日の `Daily/YYYY-MM-DD.md` の `## 📝 Log` に `- HH:mm 内容` で 1 行足し、回答の最後に「📝 Obsidian」見出しで報告する。

## メモ
